# 文章质量评估标准（v6，2026-10-09 定稿，2026-10-10 补充合并规则与边界）

judge（`eval/judge/`）按本标准评每一篇语料。模型只负责**找问题并给证据**；结论由程序按问题计算。`eval/judge/rubric.ts` 的提示词是本文的英文版，两者必须一致，改一处就改另一处并升 `RUBRIC_VERSION`。

## 1. 真值来源

- **内容**以原页快照（`eval/corpus/<slug>/page.html.gz`）为准，即抽取器当时看到的页面。快照本身没有的内容不在评估范围内。
- **显示效果**以阅读器的实际渲染为准（`eval/render` 的截图，默认阅读设置、浅色、1280 宽）。
- **量测事实**（程序算出的坏图、溢出、裸标记、公式错误、无标记列表、空单元格表格、图片清单、嵌入清单）是真值。与事实矛盾的问题不计入结论。

## 2. 文章边界

| 必须保留（缺了是问题） | 必须去掉（留着是次要问题，去掉从来不是问题） |
|---|---|
| 正文段落与标题、列表、引用 | 导航、面包屑、目录侧栏 |
| 代码块、公式、表格 | 相关文章、推荐阅读、"更多来自…" |
| 图片及图注 | 评论区、"在 HN 讨论"等外链区 |
| 脚注 | 分享、订阅、newsletter、广告 |
| 提示框 / 注意 / 说明（callout、admonition、note、key point） | 作者简介卡、头像卡 |
| 需要 JavaScript 才能显示的正文内容：交互示例、嵌入视频 / 推文、动态图表——阅读器应显示它本身，或至少一个指向它的链接 / 占位 | 版权、许可证、商标页脚 |
| | 站点模板给每篇文章加的「引用本文 / BibTeX」块（2026-10-10 定） |
| | 订阅、评论、点赞、分享类服务的嵌入（newsletter 表单、Disqus、点赞小组件等） |

## 3. 三层，各自给结论

| 层 | 检查什么 |
|---|---|
| **内容**（抽取器） | 正文从第一段真正的正文开始、在文章结束处结束；边界内的东西都在、顺序对、不重复；边界外的东西没混进来 |
| **元数据**（抽取器） | 标题、作者、发布日期 |
| **渲染**（阅读器） | 每个元素在阅读器里显示正确：没有裸标记、坏图、超出栏宽、未渲染公式、乱掉的表格、压成一行的代码、丢失的列表标记；原页的图、表、代码、公式在阅读器里都在且可读 |

总结论 = 三层中最差的一层。

**内容与渲染的分界**（2026-10-10 澄清）：看抽取结果里有没有这个元素。

- 抽取结果里**没有**或不完整（缺图、缺提示框、表格里的 ✓/✗ 图标没抽到所以单元格是空的、嵌入连链接都没留）→ **内容层**，要修的是抽取器。
- 抽取结果里**完整**，但阅读器显示错了（图片加载失败、公式没排版、代码换行在抽取结果里有而显示时丢了、列表没有标记、超出栏宽）→ **渲染层**，要修的是阅读器。

程序按事实定层：引用了未匹配原图、未显示嵌入或空单元格表格的问题归内容层；引用了坏掉的阅读器图片的问题归渲染层；引用了压成一行的代码块时，抽取结果里这段代码仍有换行则归渲染层，否则归内容层。

图片（r…/o…）、嵌入（e…）、表格（t…）、代码块（c…）都有编号，模型须在问题里引用相关编号。

## 4. 严重度：按读者损失了什么

**严重（major）**——信息丢失，或元素无法阅读：

- 缺正文段落、小节、提示框、图、表、脚注、代码块、公式
- 需要 JavaScript 的正文内容（交互示例、嵌入、动态图表）在阅读器里完全消失，连链接或占位都没有
- 代码块压成一行或被截断、公式显示为源码或错乱、表格单元格丢内容或结构塌掉、图片坏掉
- 标题错误（不是这篇文章的标题、混入站名或界面文字、取错了标题）
- 正文顺序错乱、整段重复
- 抽成了别的东西（只抽到摘要、抽到了导航页）

**次要（minor）**——信息都在，但看得出不对：

- 作者或发布日期缺失、错误（页面上明明有）
- 边界外的东西留在正文里（作者卡、订阅块、许可证页脚）
- 标题层级不对、标题里带永久链接残留、段落被拆开或合并、列表被压平但内容都在
- 缺图注、空标题、标题在正文里重复一次
- 间距、换行等排版瑕疵

不是问题：去掉了边界外的东西；原页自己就有的缺陷（参照截图里同样坏掉）；Markdown 写法上的差异（只要阅读器显示正确）。

## 5. 结论怎么算（程序）

每层：有任一**有效的**严重问题 → MAJOR；否则有任一有效的次要问题 → MINOR；否则 PASS。总结论取三层最差。

问题**有效**须同时满足：

1. 证据是逐字引文（来自原页文本、抽取结果或阅读器可见文本），程序能在输入里找到。比对按可见文字：忽略空白、Markdown / HTML 标记与转义，弯引号与直引号等同，引文末尾的省略号不算；但词必须都在、顺序一致；
2. 不是边界外内容的缺失（按 §2 无效）：声称"缺内容"而引文是版权、许可证、商标声明或引用本文 / BibTeX 块的；声称缺图或缺嵌入，而所引原图 / 嵌入紧前面的文字不在抽取结果里（即它不在文章范围内，如页底的相关文章缩略图）；前面没有任何文字的图（在标题之前，如站点 logo、页头图）也不在范围内；紧跟在文章标题、作者或日期行之后的图和嵌入算在文章范围内；所引嵌入来自订阅、评论、点赞、分享类服务的；
3. 不与量测事实矛盾——声称阅读器缺某张图，而图片清单显示这张图在阅读器里且没坏，该问题无效；
4. 截图位置（`where`）指向实际发给模型的截图块，引用的编号确实存在。

无效问题仍保存在结果里（标明原因），报告里可见，但不计入结论。

"边界外的东西留在正文里"一律为次要，由程序封顶（`extra_content` 类问题不会是严重）。

元数据问题由程序定层和严重度：模型须标明是关于标题、作者还是日期；标题问题一律为元数据层严重，作者和日期问题一律为元数据层次要，不论模型怎么标。

## 6. 双模型策略

Claude Sonnet 5 先评每一篇；任何一层不是 PASS，就交给 Codex GPT-6-Luna 复评。只有一份意见的篇目，按这份意见的有效问题算结论。

有两份意见时**交叉确认**（2026-10-10 定）：

- 两个模型都报了的问题算一次，严重度取两者中较重的。"同一个问题"指：两边引用的编号有交集（此时不看层和类）；两边都没引用编号时，须同一层、同一类。
- 只有一方报的**严重**问题降为次要，除非有量测事实支撑：引用了在文章范围内的未匹配原图、坏掉的阅读器图片或未显示的嵌入；引用了空单元格表格或压成一行的代码块；或者是渲染层的图片问题且有坏图、表格问题且有空单元格表格、代码/公式或排版问题且有裸标记、公式错误或压成一行的代码。有事实支撑的，一方报就按严重计。
- 只有一方报的次要问题照常计入。

两者的结论不同时标记"有分歧"；两份意见、合并后的问题清单及每条问题的来源（双方 / 一方 / 一方但有事实支撑 / 降级）都保存在结果里。

## 7. 重新计分

结论、有效性与合并都是程序算的，所以标准里程序部分的改动不必重新调用模型：`pnpm --filter @read/eval judge --rescore` 用保存的两份意见和当前的采集事实重新校验、合并、计算结论，并与基线比较。只有提示词（模型看到的内容）变了才需要重新评。
