# Extraction & Rendering Quality Review

Reviewed: 64 docs in `eval/out/` (of 66 entries in `eval/corpus.json` — see missing-docs note below). Sample for Part B: 15 docs per the requested stratification (lilian-attention covers both the math and tables slots).

All findings below were verified against the actual files with `head`/`tail`/`rg`/`sed` and, for Part B, against the live rendered page — including two corrections made *after* visually checking the app (see notes on raw-HTML tables and the duplicate-title bug), because the raw `extracted.md` text alone was misleading in those cases.

---

## 1. Summary

**Part A verdicts (64 docs):** 36 PASS · 6 MINOR · 22 MAJOR.
**Missing entirely:** `bair-koala` and `coolshell-rust` are in `corpus.json` but have no `eval/out/` directory at all — no `source.txt`, `extracted.md`, or `summary.json`. That's a hard pipeline failure, not a quality defect, and it means the corpus is actually 66 URLs, not 64.

**Overall impression:** metadata (title/byline/date) is right more often than not, and math/tables/images/footnotes render well when the underlying markdown is clean — KaTeX in particular is genuinely good, including multi-line aligned equations and equation numbering. But there is one very-high-frequency cosmetic bug (duplicated title heading, ~44% of docs), one very-high-frequency structural bug (leftover heading-permalink markup, ~38% of docs), and a small but severe cluster of MAJOR bugs where the extractor keeps site chrome (related-post cards, author bio blocks, "Also in Computer Science" widgets) as if it were article body. A handful of individual bugs are worse than their frequency suggests: one long essay renders as a single 11,600-word paragraph, one footnote shows raw un-rendered LaTeX, and one code sample got flattened into a single inline-code line with all its newlines removed.

**A design note, not a defect:** two things I initially flagged from the raw `extracted.md` text turned out to render *correctly* once checked in the browser, and I want to be explicit about walking them back so they aren't miscounted:
- **Raw escaped HTML (`\<table>\<tbody>...`) in the markdown** (found in `ciechanowski-gps, huyenchip-llm-eng, jalammar-transformer, joshwcomeau-rerender, openai-4o, ruder-optim, webdev-vitals`) looks alarming in the `.md` file, but the reader's markdown renderer supports raw-HTML passthrough, so both instances I checked on screen (`jalammar-transformer`'s book-promo callout, `ruder-optim`'s two-column GIF comparison) rendered as clean, correctly laid-out boxes. It's still not *clean* markdown (it would break in any renderer without HTML passthrough, e.g. plain-text or a different app), but it is not currently a user-visible bug in this reader.

## 3. Part B — rendering notes (15 sampled docs)

For each: opened via double-click from Library, screenshotted at the top and after scrolling, checked headings/code/math/tables/footnotes, Escaped back to the list. The right-edge tick rail (contents) is present and visible once an article is open (thin tick marks along the right edge, one per heading) — confirmed in every doc opened. Images show as bordered "Image unavailable" placeholders per the known CSP limitation — not reported as a finding.

**fasterthanlime-golang** (code-heavy). Top: clean. Mid-scroll: the H2 "Garden-variety takes on Go" renders in the *same blue as inline links*, with no bold/black heading styling at all (DOM role is `link`, not `heading`) — a real, confirmed heading-hierarchy defect. The article's largest code sample (the Go `File`/`FileInfo`/`FileMode` type definitions) is **not a fenced code block** in `extracted.md` at all — grep confirms zero `` ``` `` in the file — it's a single inline-code span with every newline collapsed to a space, and a stray private-use Unicode character (`U+E65E`, an icon-font leftover from the source page) sits right before the opening backtick. Despite that, the reader displays it as a properly multi-line, indented code box — it appears to apply its own heuristic re-formatting to long inline-code spans, which is a fragile compensation for a genuine extraction bug rather than something to rely on. No syntax-highlighting color on this Go snippet.

**jaykmody-gpt** (code-heavy). Top: clean, tick rail visible. Python fences (` ```python `) get full syntax highlighting — keywords, strings, function names all correctly colored, and inline code pills (`numpy`) render with a gray badge.
