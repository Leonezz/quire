## 2. Findings, most severe first

### MAJOR

1. **`apps/desktop/src/main/engine/materials.ts:194-201` (`saveArtifact`) — citation/lineage is validated against "exists in the library", not "was actually used this turn".**
   What happens: the only check on `artifact_write`'s `lineage` array is `this.read(id)` returning something — i.e., the id is *some* material in the library. Nothing in `agent-tools.ts`, `agent.ts` or `codex-client.ts` tracks which ids were actually returned by a tool call during the turn.
   What should happen: an artifact's lineage should only admit ids the model actually retrieved (searched or read) in that turn, otherwise the reader-facing "materials this claim is based on" list (contracts.ts's own `lineage` doc-comment: "so every claim has a trail") is not a trail at all — a model can name any real library id as a source it never opened, and it will save and render as a trustworthy citation.
   Verified: read `agent-tools.test.ts:114-117` — it only tests a *nonexistent* id being rejected; no test exercises an existing-but-unread id, because today there is no mechanism to reject it.

2. **`apps/desktop/src/main/engine/codex-client.ts:356-359` (`interrupt`) — Stop is a silent no-op in a real, easily-hit window.**
   What happens: `if (!turn?.turnId) return;` — if the user presses Stop before the server's `turn/start` ack has assigned a `turnId` (the buffered-early-events window the same file already accounts for elsewhere), `interrupt()` resolves successfully having sent nothing. The turn runs to completion with no indication Stop did anything.
   What should happen: Stop pressed in that window should either queue the interrupt for as soon as `turnId` arrives, or surface "could not stop yet" — not silently succeed.
   Verified: read the full `interrupt()`/`runTurn` implementation; grepped both `codex-client.test.ts` and `agent.test.ts` — only the "turn already has a turnId" interrupt path is tested; `AgentService.interrupt()` itself has no test that calls it against a live fake client.

3. **`apps/desktop/src/main/index.ts:141-149` vs `:150` — per-source "Sync now" bypasses the scheduler's own overlap guard.**
   What happens: `source:syncAll` (bulk) correctly shares `scheduler.tick()`'s in-flight promise (comment at line 148 even says so: "Shares the scheduler's in-flight run, so a manual refresh never overlaps a scheduled one"). But `source:sync` (the per-source "Sync now" button) calls `syncSource(source, …)` directly, with no lock at all. A user clicking "Sync now" on one source at the same moment the 15-minute scheduler fires and picks up that same source races two concurrent `syncSource` calls against the same row.
   What should happen: the guarantee in the comment at line 148 should hold for single-source syncs too, not just bulk ones.
   Downstream effect (verified in `items.ts`): `upsert`'s "added" count is computed via a `before`/`after` count pair around the transaction; two overlapping calls for the same source can both snapshot the same `before`, inflating the `added` count the UI shows as "N new". `sources.ts`'s `updateHealth` writes `failureCount + 1` from an in-memory snapshot rather than atomically in SQL, so the loser of the race can clobber the winner's `lastError`/`failureCount`.
   Verified: read `index.ts` end to end for both handlers; read `scheduler.ts` (its single-flight `tick()` is correctly implemented and tested at `scheduler.test.ts:23-38`); confirmed no test in `sync.test.ts` or `scheduler.test.ts` combines a per-source sync with a concurrent scheduler tick.

4. **`apps/desktop/src/main/engine/reading-time.ts:5-17` — CJK reading time overcounts on punctuation; affects most non-English items.**
   What happens: `CJK = /[\p{Script=Han}\p{Script=Hiragana}\p{Script=Katakana}\p{Script=Hangul}]/gu` does not match full-width CJK punctuation (`。`，`！`, `？`, …), which is Unicode script `Common`. Both `wordCount` and `readingMinutes` replace only CJK-script characters with a space and then split on whitespace, so each isolated punctuation mark between two space-replaced characters becomes its own phantom "word".
   What should happen: punctuation should be stripped (not counted as a word) alongside the CJK characters it sits between.
   Verified by direct execution: on `"你好,世界。这是一个测试,包含标点符号。"` (16 real characters, 0 real words), `wordCount` returns **20**, a ~25% overcount. Since virtually all real Chinese/Japanese/Korean feed prose carries full-width punctuation, this skews `readingMinutes` on nearly every CJK item. `reading-time.test.ts` has zero cases containing CJK punctuation (its three CJK assertions are punctuation-free).

5. **`apps/desktop/src/renderer/src/useItemReader.ts:37` (`decisionError`) — not scoped per item, unlike `failure`; leaks onto the next-selected item.**
   What happens: `failure` is `{itemId, message}` and is correctly gated at the call site (`failure?.itemId === current.id`, `InboxView.tsx:56`, `QueueView.tsx:83`). `decisionError` is a bare `string | undefined`, passed unconditionally (`InboxView.tsx:56`, `QueueView.tsx:83` — `error={decisionError}`), and is only cleared when a *new* decide/readNow starts (line 47/60) — never when the selection simply changes.
   What should happen: if deciding item A fails, then the user moves to item B (arrow keys, click, or the automatic post-decision selection move), item B should not show "Could not queue this item" about itself.
   Verified: read `useItemReader.ts` end to end; `select()` (line 44) only resets `reading`/`failure`, not `decisionError`; no test exercises this (no test file exists for this hook — see finding 10).

6. **`apps/desktop/src/renderer/src/QueueView.tsx:56-61` (`persist`) — reorder has no request-generation guard; a fast double-reorder can silently drop one move.**
   What happens: `persist(order)` computes `order` from the closures `continuing`/`upNext`, which only reflect the *previous* server state until `refresh()` (called in `.finally`) resolves and parent state updates. A second reorder fired before the first's `refresh()` completes computes its base order from the pre-first-drop list, and its `reorderQueue` call — a hard `ids` replace in both the real engine (`items.ts`) and `previewM1.reorderQueue`) — overwrites the backend with an order that doesn't include the first move.
   What should happen: this exact problem is already solved elsewhere in the same codebase — `SearchPalette.tsx` guards against a stale response with a `generation` ref (lines ~15/21/26-28). `QueueView` should do the same before calling `reorderQueue`.
   Verified: read `persist`, `useLists.refresh`, and `previewM1.ts`'s `reorderQueue` (hard `ids.indexOf` replace, no CAS/merge semantics). Not tested (no test file for `QueueView.tsx`).

7. **`apps/desktop/src/renderer/src/AgentPanel.tsx:21-42` / `ReaderView.tsx:255` / `PdfReaderView.tsx:157` — context pill and canned-prompt subject are hardcoded literals, not the material's title.**
   What happens: `subject` is passed in as the literal string `"this article"` or `"this PDF"` regardless of which document is open; `contextLabel`/`promptLabel` (AgentPanel.tsx:23-35) just echo it back. Every article's and every PDF's agent conversation reads identically ("Explain this article", context pill "this article").
   What should happen: pass the actual `material.title` (already in scope at both call sites) so the panel and its canned prompts identify *which* document the conversation is about — directly relevant to the review's "does the panel make context obvious" question.
   Verified: read both call sites and `AgentPanel.tsx`'s default (`subject = "this material"`, line 42).

8. **`apps/desktop/src/renderer/src/App.tsx:51-62,138` — ⌘J / the Ask button is a dead click in Library with nothing selected.**
   What happens: the shell's ⌘J listener is wired `if (view !== "library") { … }` (line 51), and the `AskButton` itself is hidden in the Library view (`{view !== "library" ? <AskButton.../> : null}`, line 138). With nothing selected in Library, the right pane shows only "Nothing selected" — there is no way to reach the agent at all, even though `AgentContext {kind:"library"}` is fully implemented and is exactly the context this scenario needs (and is reachable from every *other* view).
   What should happen: ⌘J / Ask should be available in Library too, defaulting to the library-wide context when nothing is selected — this is the specific "nothing selected in Library" scenario the review asked about, and today it's a dead end, not a sensible empty state.
   Verified live: opened Library with no selection in the browser preview — no Ask affordance is rendered; confirmed the same restriction in the source at both cited lines.

9. **`apps/desktop/src/renderer/src/AgentMarkdown.tsx:78-105` (`renderInline`) — citation pills render unconditionally; nothing distinguishes a real citation from a hallucinated one.**
   What happens: any `[16-hex-chars]` token the model streams becomes a `CitationPill` (lines 90-92) with the same chrome regardless of whether that id was ever returned by a tool call this turn. `AgentPanel.tsx` loads a `titles` map (lines 61-67) only to pick a *label* after the fact, never to gate rendering. A fabricated id gets an 8-hex-char fallback label indistinguishable at a glance from a real one; clicking it only reveals "no longer in the library" after navigating into `MaterialReader`.
   What should happen: given finding 1 (server-side lineage isn't validated against "used this turn" either), there is currently no point in the pipeline — prompt, tool layer, or renderer — where a hallucinated citation is caught before it reaches the reader looking exactly like a real one.
   Verified: read `renderInline` and `AgentPanel.tsx`'s title-map usage; confirmed live in the demo panel that a real id (`526130b61f003c33`) resolves to its title ("CSS Custom Highlight API") correctly — the *labeling* mechanism works, it's the *validation* that's absent.

10. **Renderer app-logic layer has zero automated test/story coverage, unlike the primitives underneath it.**
    What happens: `fd -e test.ts -e test.tsx -e stories.tsx . apps/desktop/src/renderer/src` returns nothing. `InboxView`, `QueueView`, `SourcesView`, `AddSheet`, `SearchPalette`, `useLists`, `useItemReader`, `AgentPanel`, `AgentMarkdown`, `ArtifactLineage`, `useAgent`, `SelectionToolbar` are all untested. Meanwhile `packages/ui/src/stories/{ItemList,CommandPalette,AgentTranscript}.stories.tsx` have solid `play`-function interaction tests (keyboard grid nav, keyboard DnD reorder via grip/Enter/arrows, ⌘K-style search, resolved/unresolved citation pill activation).
    What should happen: findings 5, 6, 7, 8 and 9 all live in the untested app-logic layer, not the well-tested primitives — that's exactly the gap the primitives' tests can't see into.
    Verified: `fd` search returned empty; cross-checked `packages/ui`'s story files directly for their `play` functions to confirm what *is* covered.

11. **`apps/desktop/src/renderer/src/SourcesView.tsx:38-47` (`remove`) — a failed Disconnect is rendered behind the still-open confirm modal.**
    What happens: on failure, `actionError` is set but `confirming` stays `true` (only cleared on success, line 42). The `InlineError` for `actionError` renders in the underlying page, behind the still-open, blurred `ModalOverlay` the confirm `Sheet` uses.
    What should happen: the user is staring at "Disconnect X?" with Cancel/Disconnect — the failure text exists in the DOM but they can't see it until they dismiss the dialog they're already looking at, which is a "nothing should fail silently" violation in spirit even though the string is technically present.
    Verified: read the DOM order in `SourcesView.tsx` against `Sheet.tsx`'s `ModalOverlay` (fixed, full-screen, blurred backdrop).

12. **`apps/desktop/src/main/engine/search.ts` — zero test coverage on the module wired directly into ⌘K.**
    What happens: no `search.test.ts` exists, and a repo-wide grep for `materialHits`/`itemHits`/`mergeHits` in any `*.test.ts` returns nothing.
    What should happen: given `search:query` (`main/index.ts`) has no other validation layer, this deserves the same test discipline as the rest of the engine. Reading the code (unverified by any test): `materialHits` matches only title/byline/url — consistent with the M2 `library_search` tool's own title/byline-only limitation (see finding below) — and `hostOf` silently falls back to the raw string on a malformed URL (a deliberate, reasonable choice, but untested).

13. **`apps/desktop/src/main/engine/agent-tools.ts` (`library_search`) — silently truncates queries and never searches body text.**
    What happens: matches only title/byline (not body), and truncates queries to 8 words with no signal back to the model that truncation happened.
    What should happen: for "related"/"ask about the library" tasks, the model can honestly-but-wrongly tell the user "the library doesn't have X" when X only appears in a document's body. This directly undercuts the "are citations trustworthy" question — a *miss* here is as much a trust problem as a fabricated citation.
    Verified: read `search.ts`'s `MAX_WORDS` truncation and the title/byline-only match; no test drives either behavior.

14. **`apps/desktop/src/renderer/src/useAgent.ts:96-99` / `AgentPanel.tsx:128` — most agent failure codes collapse into one generic bubble.**
    What happens: only `TURN_INTERRUPTED` gets distinct handling; `AGENT_UNAVAILABLE`, `TURN_FAILED`, `TURN_TIMEOUT` all become one `status:"failed"` rendered through an identical red `role="alert"` paragraph. The main process *does* send distinct, well-written messages per code (install hints for `AGENT_UNAVAILABLE`, a timeout explanation for `TURN_TIMEOUT`) but the renderer only shows whatever free text arrived, with no differentiated affordance (only `AUTH_REQUIRED` gets its own Sign-in button).
    What should happen: at minimum, `AGENT_UNAVAILABLE` (install/setup problem) and `TURN_TIMEOUT` (retry-able) warrant different next steps than a generic error paragraph.
    Verified: read both files; `AgentStatus.busy` (contracts.ts) is defined for exactly this kind of proactive messaging and is never read by either file (`grep ".busy"` empty) — a concurrent turn is only discovered reactively via a `TURN_RUNNING` rejection, not shown ahead of time.

### MINOR

15. **`apps/desktop/src/main/engine/sources.ts` — no setter for `intervalMinutes`; no backoff on repeated failures.** A source that fails every sync is retried at the same cadence forever; `failureCount`/`lastError` are tracked and shown, but nothing widens the interval. Verified: grepped `SourceStore` for any interval mutation — none exists.

16. **`apps/desktop/src/renderer/src/AgentPanel.tsx` — Sign-in has no busy/loading state.** `agentLogin()` can legitimately wait up to ~3 minutes for a browser redirect (per `codex-client.ts`'s login flow); the Sign-in button stays clickable the whole time, inviting duplicate invocations.

17. **`apps/desktop/src/renderer/src/SelectionToolbar.tsx` — "Ask about this" is effectively mouse-only.** The toolbar (`role="toolbar"`) never moves focus into itself when it appears and implements no roving-tabindex, despite the role implying arrow-key navigation. A keyboard-only user who makes a selection has no local, discoverable path to "Ask about this".

18. **`apps/desktop/src/main/index.ts` (`addSource`'s catch) — hardcodes `code:"SOURCE_EXISTS"` for any thrown error**, not just the duplicate-source case. Accurate today only because `SourceStore.add` happens to throw exactly one kind of error; a future second throw site would be mislabeled to the UI.
19. **`apps/desktop/src/main/engine/inbox.ts` (`materializeArxiv`) — on a double failure (HTML then PDF), the returned `code` is always the PDF failure's code**, discarding the HTML failure's code even though both messages are concatenated into the text. A caller keying behavior off `code` loses the root cause.
20. **`apps/desktop/src/renderer/src/AgentPanel.tsx` / `ArtifactLineage.tsx` — duplicated `listMaterials().then(...).catch(...)` title-map logic** in both files; a failure shows two redundant "could not load" alerts if both are open. Candidate for a shared `useMaterialTitles()` hook.
21. **`apps/desktop/src/main/engine/db.ts` — no `db.test.ts`**; the "open a DB from a newer build" (`version > SCHEMA_VERSION`) throw path is untested. Schema application isn't wrapped in one transaction (mitigated by `IF NOT EXISTS`, low real risk).
22. **`packages/core` has no tests at all** (`test` script is literally `echo 'core: no tests yet'`) — flagged since it's a shared package other workspaces depend on.

### Positive findings worth keeping

- Every IPC handler in `main/index.ts` validates and bounds its input before touching a store (`boundedString`, byte caps, enum membership) — no unvalidated or over-broad surface found anywhere in the preload/IPC boundary.
- Approval-always-decline and read-only sandbox (`approvalPolicy:"never"`, `sandboxPolicy:{type:"readOnly"}`) are correctly wired on both `thread/start` and `turn/start`, and covered by a test (`codex-client.test.ts`) that asserts a decline doesn't end the turn.
- `reorderQueue`'s mismatched-ids handling (missing/duplicate/extra ids → `QUEUE_ORDER_MISMATCH`) is correctly implemented **and** already well tested (`items.test.ts`).
- The Sources Disconnect confirmation is a real, undismissable-mid-request modal with Cancel/Disconnect (verified live) — undermined only by finding 11 above, not absent.
- `AgentMarkdown`'s streaming parser re-parses the full accumulated string on every delta, so unterminated code fences/citations simply stay plain text until complete — no flash of broken formatting (verified live in the demo panel).
- `ArtifactLineage` degrades gracefully for a deleted lineage material ("Material `<id>` (no longer in the library)") instead of crashing, and is fully keyboard-operable (native `<details>/<summary>`, `<button>`s).
- The core keyboard triage loop (Enter = Read now, q = Queue, e = Dismiss, selection follows the decision to a sensible neighbour) was verified live end-to-end and works correctly — this is the loop the "100 items in 5 minutes" question hinges on, and it holds up.

## 3. Top 10 fixes, in priority order

1. Make agent citations trustworthy end to end: `saveArtifact`'s lineage check (`materials.ts:198-201`) and any transcript citation pill should require the id to have actually been surfaced by a tool call *this turn*, not merely exist in the library (findings 1, 9).
2. Fix the CJK reading-time overcount (`reading-time.ts:5-17`) — strip punctuation, don't count it as a word; add a punctuation-bearing test case (finding 4).
3. Close the per-source "Sync now" race: route `source:sync` (`main/index.ts:141`) through the same single-flight guard `source:syncAll`/`scheduler.tick()` already provides, or lock per-source (finding 3).
4. Scope `decisionError` by item id (mirror `failure`'s `{itemId, message}` shape) and/or clear it in `select()` in `useItemReader.ts` (finding 5).
5. Add a request-generation guard to `QueueView.persist` the same way `SearchPalette` already does, so a fast double-reorder can't silently drop a move (finding 6).
6. Pass the material's real title into `AgentPanel`'s `subject` instead of the "this article"/"this PDF" literals (finding 7).
7. Wire ⌘J/Ask into the Library view with the `{kind:"library"}` context when nothing is selected, instead of hiding the affordance entirely (finding 8).
8. Fix `CodexClient.interrupt()`'s silent no-op when Stop is pressed before `turnId` is assigned (finding 2).
9. Differentiate `AGENT_UNAVAILABLE` / `TURN_FAILED` / `TURN_TIMEOUT` in the panel instead of one generic red bubble, and surface `AgentStatus.busy` proactively (finding 14).
10. Add tests/stories for the untested renderer app-logic layer (`useItemReader`, `QueueView`, `SourcesView`, `AgentPanel`, `AgentMarkdown`) — this is where findings 5–9 and 11 all live, and it's the one layer with no automated net under it today (finding 10).
